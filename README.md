# Decision room

A phone-first web app for the Hardware Co Customer Sales operating model. Each executive chooses High, Medium or Low for seven priorities on their own phone. The facilitator's screen shows only a count until the results are revealed, then shows where the room agrees, where it splits, and which splits would change the recommended option. The facilitator records the agreed choices and downloads a decision record.

Hardware Co is a fictional client and all figures are synthetic.

**Open it:** https://s-richardson.github.io/hardware-co-decision-room/

## Running a session

1. **Facilitator:** open the app, choose **Run a room** and put the screen on the projector. It shows a QR code and a six-character code.
2. **Executives:** scan the QR code with the phone camera (or open the app, choose **Join a room** and type the code). They step through seven priorities, check their choices and send them. They can change them until voting closes.
3. **Facilitator:** when the count matches the people in the room, choose **Close voting and reveal**. Results appear on the screen and on every phone.
4. **Discuss** the splits that change the answer, then use the **Record** tab to set the agreed choices, add notes and download the record as Markdown.
5. **Start a new round** to vote again after discussion. Phones prompt everyone to vote again.

Anyone without a phone: the facilitator enters their choices on the **Add by hand** tab. To run with no network at all, choose **Run it without phones** and enter everyone's choices on one device.

## Save it as an app

- **iPhone:** open the link in Safari, tap Share, then **Add to Home Screen**.
- **Android:** open the link in Chrome, then **Install app** (or **Add to Home screen**) from the menu.

It opens full screen with its own icon, and the app itself works offline. Live voting needs a connection.

## How live voting works on GitHub Pages

GitHub Pages only serves static files, so phones and the facilitator's screen exchange messages through [ntfy.sh](https://ntfy.sh), a free, open-source publish and subscribe relay. No account or server setup is needed.

- Every message is encrypted on the device with AES-GCM. The key is derived from the room code (PBKDF2, 150,000 rounds), and the room code never leaves the devices.
- The relay channel name is a one-way hash of the code, so the relay sees only a random-looking channel and ciphertext.
- Votes carry a random per-phone ID and the seven choices. No names, emails or device details are sent.
- ntfy.sh keeps messages for about 12 hours. A facilitator can reload the page in that window and the room is rebuilt from the relay.
- Anyone who has the code can join, so share it only in the room.
- If a venue's network blocks ntfy.sh, use **Add by hand**. ntfy can also be self-hosted; change `DEFAULT_BASE` in `js/relay.js`.

## Scoring

The scoring is identical to the decision tool:
- **Points:** High earns 4 points, Medium 2 and Low 1. Appetite for change is inverted.
- **Weights:** each priority's points are split across the criteria it measures, and the weights are normalised to 100.
- **Totals:** each option's 0 to 10 criterion scores are weighted and added. Ties go to the recommended option.
- **The room's choice:** for each priority it is the most common answer. Ties go to Hardware Co's brief, then to Medium.
- **Splits that change the answer:** a split counts if moving that one priority to another level that someone chose changes the leading option.

## Files

| Path | What it holds |
| --- | --- |
| `index.html` | Page shell |
| `js/app.js` | The app: home, facilitator, phone voting, results, record |
| `js/relay.js` | Encryption and the ntfy relay |
| `js/content.js` | Priorities, levels, criteria, options and scores, generated by `tools/extract.js` from the decision tool's `data.js` |
| `js/vendor/qrcode.js` | QR code generator (Kazuhiko Arase, MIT licence) |
| `css/app.css` | Styles |
| `sw.js`, `manifest.webmanifest`, `icons/` | Install and offline |
| `fonts/` | Open Sans (SIL Open Font License) |
| `tests/` | Playwright tests: `e2e.py` (a facilitator and four phones through the live relay), `shots.py` (layout at five sizes), `offline.py` (no-phone mode and offline start) |

To update the content after the decision tool changes: `node tools/extract.js ../hardware-co-opmodel/src/js/data.js > js/content.js`, then bump `CACHE` in `sw.js`.

To test locally: `python3 -m http.server 8765`, then `python3 tests/e2e.py http://localhost:8765/`.
